# 1. Суть кейса

## 1.1. Цель системы (миссия)

Обеспечить точный, прослеживаемый и устойчивый к сбоям оборот товара на складе электронной коммерции — от приёмки поставки до передачи заказа курьерской службе — за счёт пошагового сопровождения операций со сканированием, контроля расхождений в режиме реального времени и интеграции с OMS/ERP и курьерскими службами. Система минимизирует ошибки оператора, сохраняет работоспособность при плохой сети и обеспечивает аудит всех складских действий.

## 1.2. Контекст (среда и внешние системы)

### 1.2.1. Пользователи

| Роль | Описание роли | Поведение |
| --- | --- | --- |
| Кладовщик | Линейный сотрудник, выполняющий физические операции на складе. Работает с ТСД и/или планшетом. В сценариях упаковки (§2.7) обозначается термином «Упаковщик» — это специализация роли «Кладовщик», работающего в зоне упаковки; набор прав и интерфейс не отличаются от общего профиля Кладовщика | Получает задачи на приёмку/размещение/сборку/упаковку/инвентаризацию на ТСД. Сканирует штрихкоды товаров, ячеек, упаковок. Ожидает чётких пошаговых инструкций, минимального ручного ввода, обратной связи об ошибках. Может работать в зонах слабой связи, не должен утрачивать данные текущей операции при потере связи Wi-Fi |
| Супервайзер | Руководит сменой кладовщиков, распределяет задачи, следит за прогрессом | Видит данные по статусам задач, производительность по сотрудникам. Может управлять задачами, перенаправлять их, утверждать корректировки. Ожидает оперативный отклик, понятные уведомления о критических событиях, возможность выполнять CRUD-операции над задачами |
| Менеджер по логистике | Управленческая роль. Планирует загрузку склада, отслеживает SLA, согласовывает процессы с OMS/ERP и курьерскими службами | Работает преимущественно с админкой и отчётами: настройка зон/ячеек, правил приоритизации заказов, расписания инвентаризаций. Ожидает достоверные данные, экспорт, аудит |
| Служба поддержки | Первая линия для внутренних обращений | По номеру заказа/трек-номеру восстанавливает историю: что было собрано, кем, когда, какой курьер забрал заказ. Ожидает единое окно, журнал действий, возможность инициировать перепроверку |
| Администратор системы | Технический владелец конфигурации | Настраивает пользователей, роли, права доступа, справочники склада, зоны хранения, ячейки, интеграции, правила печати этикеток и параметры синхронизации |

### 1.2.2. Исполнители

Под «исполнителями» здесь понимаются системные субъекты внутри SoI, которые автономно выполняют действия в ответ на события (в отличие от пользователей-людей из §1.2.1).

| Исполнитель | Назначение | Поведение |
| --- | --- | --- |
| Сервис заданий (Task Service) | Формирует и распределяет задания на приёмку, размещение, сборку, упаковку и инвентаризацию между кладовщиками | Принимает события из OMS/ERP и от супервайзера, формирует задание, выбирает исполнителя по правилам приоритизации, отслеживает SLA выполнения |
| Сервис рекомендаций по ячейкам | Подбирает оптимальную ячейку при размещении товара | Учитывает тип товара, температурный режим, габариты, текущую загрузку ячейки и правила хранения. Возвращает ранжированный список допустимых ячеек |
| Сервис синхронизации с OMS/ERP | Передаёт статусы складских операций во внешний учётный контур и принимает оттуда заказы/поставки | Слушает события (приёмка, размещение, сборка, отгрузка), формирует идемпотентные сообщения, ведёт очередь повторной отправки при сбое OMS/ERP |
| Сервис интеграции с курьерами | Регистрирует отправления в API курьерских служб и получает трек-номер и транспортную этикетку | По завершении упаковки отправляет запрос регистрации, сохраняет трек-номер, обрабатывает ошибки регистрации, поддерживает выбор альтернативной службы |
| Сервис печати этикеток | Управляет очередью печати складских, товарных и транспортных этикеток | Получает запрос на печать, выбирает доступный принтер, ставит в очередь при недоступности, поддерживает повторную печать без повторной регистрации |
| Сервис уведомлений | Доставляет уведомления супервайзеру, менеджеру логистики и службе поддержки при критичных событиях | Слушает критические события (расхождения, сбои интеграций, превышение порогов очереди синхронизации), отправляет по почте/в админ-интерфейс |
| Планировщик инвентаризаций | Создаёт задания на плановую и циклическую инвентаризацию по расписанию | По расписанию или триггеру (расхождение остатков, сборка с недостачей) формирует задание на инвентаризацию ячейки, зоны или товара |
| Агент мобильного клиента (автономный режим) | Локальный субъект на ТСД/планшете кладовщика, выполняющий операции при потере сети | Кэширует справочники и задания, фиксирует операции локально, ставит их в очередь синхронизации, отслеживает статус соединения |

### 1.2.3. Интеграции

| Внешняя система | Назначение | Направление | Канал |
| --- | --- | --- | --- |
| OMS/ERP | Источник заказов, поставок, карточек товаров; приёмник статусов складских операций и корректировок | двунаправленная | REST (синхронный вызов) + Apache Kafka [1] (события статусов) |
| Курьерские службы (СДЭК, Boxberry и т. п.) | Регистрация отправлений, получение трек-номера и транспортной этикетки, отслеживание статуса доставки | двунаправленная | REST/HTTPS API курьеров |
| Сервис печати этикеток (внешний драйвер/CUPS) | Печать товарных, складских и транспортных этикеток | исходящая | IPP/CUPS, локальные драйверы принтеров |
| Сканеры штрихкодов | Идентификация товара, ячейки, упаковки, заказа, транспортной этикетки | входящая | HID-клавиатура (по умолчанию), Bluetooth/USB |
| IdP/SSO (внешний провайдер) | Авторизация и единый вход пользователей системы | исходящая | OAuth 2.0 [2] / OpenID Connect 1.0 [3] / SAML 2.0 [4] |
| Почтовый сервер (SMTP) | Отправка уведомлений о критичных событиях и отчётов | исходящая | SMTP/SMTPS |
| Внешний мониторинг (Prometheus/Zabbix) | Сбор технических метрик доступности, нагрузки, очередей | исходящая | HTTP pull (/metrics) или push в Zabbix |
| BI / аналитика (опционально) | Выгрузка агрегированных данных по операциям склада для отчётности | исходящая | Витрина данных / экспорт CSV/Parquet, JDBC |

Каждая интеграция учтена в режимах деградации §2.3 и в реестре рисков §6 (см. R-06, R-09, R-10).

## 1.3. Границы SoI (System of Interest)

### Внутри SoI (под нашей ответственностью)

1. **Прикладные сервисы**
1.1 Сервис заданий (приёмка, размещение, сборка, упаковка, инвентаризация).
1.2 Сервис рекомендаций по ячейкам.
1.3 Сервис синхронизации с OMS/ERP.
1.4 Сервис интеграции с курьерскими службами.
1.5 Сервис печати этикеток.
1.6 Сервис уведомлений.
1.7 Планировщик инвентаризаций.
2. **Хранилища данных**
2.1 Основная БД WMS-lite (товары, ячейки, остатки, задания, операции, пользователи).
2.2 Журнал событий и аудит-лог.
2.3 Очередь сообщений (для интеграций и синхронизации).
3. **Клиентские приложения**
3.1 Мобильный интерфейс кладовщика (с локальным кэшем и offline-агентом).
3.2 Административный интерфейс (супервайзер, менеджер логистики, администратор).
3.3 Интерфейс службы поддержки (read-only поиск по номеру заказа/трек-номеру).
4. Подсистема отчётности и мониторинга операций (отчёты по операциям, SLA, конфликтам синхронизации).
5. Подсистема ролевого доступа и локального fallback-входа (PIN-сессия при недоступности SSO).

### Снаружи SoI (внешние сущности, с которыми мы взаимодействуем, но не управляем)

1. **OMS/ERP** — источник заказов и поставок, приёмник статусов.
2. **IdP/SSO** — внешний провайдер аутентификации.
3. **Курьерские службы** — внешние API регистрации отправлений.
4. **Почтовый сервер (SMTP)** — внешний канал доставки уведомлений.
5. **Сканеры штрихкодов и принтеры этикеток** — внешние устройства/драйверы.
6. **Внешний мониторинг** — система сбора метрик (Prometheus/Zabbix/Grafana).
7. **BI / аналитика** — внешний приёмник агрегированных данных (опционально).
8. **Поставщики и курьеры (физические лица)** — источники товара и получатели отправлений.

### Ключевые ограничения границы

1. **Финансовый учёт ведётся в OMS/ERP**, не в WMS-lite. WMS отвечает только за физический оборот товара и за количество товаров по ячейкам.
2. **Управление справочниками товаров и каталогом** принадлежит OMS/ERP. WMS получает карточки товаров, но не редактирует их.
3. **Расчёт стоимости доставки и выбор тарифа** — на стороне курьерской службы. WMS передаёт только характеристики отправления.
4. **Аутентификация пользователей** — на стороне IdP/SSO. WMS использует локальный fallback только в строго ограниченном режиме (см. R-10).

## 1.4. Контекстная диаграмма

| Внешняя сущность | Поток в SoI | Поток из SoI |
| --- | --- | --- |
| Кладовщик | Сканирование штрихкодов, подтверждение количества, отметка проблем | Задания, маршрут сборки, статусы, сообщения об ошибках, рекомендации по ячейкам |
| Супервайзер | Подтверждение расхождений, переназначение задач, создание инвентаризаций | Статусы операций, очередь конфликтов, уведомления о критических событиях, отчёты по смене |
| Менеджер логистики | Настройка приоритетов, расписания инвентаризаций | Статусы заказов, SLA отгрузки, трек-номера, отчёты |
| Служба поддержки | Запросы по номеру заказа/трек-номеру | История операций по заказу, текущий статус, информация о проблемах |
| Администратор | Управление пользователями, ролями, зонами, ячейками, настройками интеграций | Логи аудита, статусы интеграций |
| OMS / ERP | Заказы, поставки, карточки товаров, отмены | Статусы приёмки/сборки/упаковки/отгрузки, корректировки остатков, события инвентаризации |
| IdP / SSO | Результат аутентификации, токен, утверждения ролей | Запросы на аутентификацию, refresh-токены |
| Курьерские службы | Трек-номер, транспортная этикетка, статусы доставки, ошибки регистрации | Данные отправления (адрес, вес, габариты, тариф) |
| Сервис печати | Подтверждение печати, ошибки оборудования | Задания печати: складские, товарные, транспортные этикетки |
| Сканеры штрихкодов | Коды товаров, ячеек, упаковок | — |
| Почтовый сервер | — | Уведомления о критичных событиях (расхождения, сбои, превышения порогов) |
| Внешний мониторинг | Запросы метрик (pull) | Метрики: глубина очередей, p95 откликов, ошибки интеграций |
| BI / аналитика | — | Агрегированные данные операций (выгрузка по расписанию) |
